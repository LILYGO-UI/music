# Music 实现说明

Music 是独立的 CM0 本地播放器，沿用 AppKit 生命周期和 MVVM 边界。K230 的 `ui_audio.c` 仅作为功能参考；没有复制 Launcher 源码。设备音乐路径、播放/暂停、切歌、随机/循环、进度与音量操作与参考保持一致。

## 界面

- 使用 iOS 风格的浅灰页面、白色圆角面板、珊瑚红强调色、大标题及分段切换。
- 界面文案、音乐库状态和错误提示统一使用英文；歌曲标题、艺人和文件夹名称保留原始内容。
- 宽屏并排呈现资料库与播放器；竖屏通过“Now Playing / Library”切换，复用相同对象。
- 刷新按钮位于 Library 标题行最右侧，用于重新扫描音乐目录。
- 所有文字使用 AppKit 的 Inter / 思源黑体 / Font Awesome 字体链。
- 封面是按对象尺寸绘制的原创几何插画，不依赖外部图片加载。它是默认占位图，不读取音频内嵌封面。
- 搜索匹配文件名推导的标题、艺人和文件夹名称；“艺人 - 歌曲”命名可识别艺人。
- 收藏过滤仅控制资料库展示；播放队列仍为完整音乐库。
- 默认目录无本地歌曲时使用原创示例；用户显式配置空目录时展示空状态。

## 数据与播放

`MusicModel` 管理队列、模式、收藏和偏好；后台扫描任务有取消标志，退出时回收。`AudioBackend` 为可注入接口，实际实现通过 `posix_spawnp` 启动 mpv，在专用线程中使用 socketpair IPC 控制播放，不使用 shell 拼接。音频路径以单独参数传递，空格、引号和中文均可保留。

mpv 的状态通知提供实际位置、时长、暂停与结束事件。自然结束依据循环模式与随机队列选曲；损坏文件、缺少播放器或输出设备异常显示可见错误，保留再次选择和重试操作。

`MusicViewModel` 将用户命令转换为模型操作，通过 RAII Subject 发布状态。`MusicView` 绑定对象 observer，使用 200ms LVGL timer 读取后台快照。销毁顺序为 View、ViewModel；timer、observer、进程、线程均由各自所有者清理。

## 验证

核心测试验证队列、重复/随机、收藏、扫描与特殊文件名，以及真实 mpv IPC（禁用音频输出）和错误路径。ViewModel 测试验证筛选、搜索和 Subject。渲染测试检查 568×1232、1232×568 视口，验证控件、旋转、空状态和长标题。生成的预览图必须额外目视检查。
